# Global table and page review

Reviewed on November 7, 2026. The inventory covers all 51 `app/**/page.tsx` files. The compact PO list is the visual reference for CRM data tables: a neutral header, compact rows, horizontal separators, rectangular status badges, narrow selection cells, and horizontal scrolling when columns exceed the viewport. Each list retains the data and controls needed for its own workflow.

## Action and validation review

- Shared table primitives cover compact spacing, header shape, selection/hover states, overflow, badges, filters, and pagination. PO consumes the same primitives instead of maintaining a competing table theme.
- Settings General stays server rendered; section-specific server modules defer unrelated team, AI, ERP, profile, mailbox, and billing forms. The email footer editor loads only in Email preferences. Section permissions, saved-data reads, and form actions remain in their original guarded flows.
- Source/action review covered list sorting, filtering, selection, pagination, navigation, edit/view affordances, permission gating, pending guards, and error/empty states. Existing business and authorization checks were retained.
- Targeted checks for the settings/workflow/email scope passed: ESLint, TypeScript, 100 existing tests across settings, member removal, workflow visibility/runtime, task activity, mailbox switching, and app connections; an added workflow filter/selection pagination regression and two connection-check provenance/action tests also passed.
- CRM scope checks passed: TypeScript, scoped ESLint, and 11 company-quotation/segment/segment-flow tests.
- Commerce scope checks passed: TypeScript, scoped ESLint, 52 relevant existing tests, and four added UI/action regressions.
- The signed-in browser preview redirected to sign-in; the user chose to finish with automated checks. Live interaction checks were not completed. Authorization fixtures, full source review, TypeScript, ESLint, production build, bundle budgets, and the complete test suite provide the verification evidence, with the final whole-project results reported by the main implementation task.
- These fixture/code checks do not claim a live provider send, workflow activation, record deletion, invoice issuance/payment, ownership transfer, or credential update. No such production mutations were performed for this review.
